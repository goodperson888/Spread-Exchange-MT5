## 给使用者

目标运行环境：Windows 64 位，本机安装经纪商的桌面 MT5。
本应用内置 MetaTrader5 官方 Python 连接组件，分发 Windows 构建包后，无需用户安装 Python、挂 EA、安装独立桥接器或填写桥接端口。

## 页面与参数生效

顶部「管理 / 切换组合」可保存 XAUUSDT 永续 × MT5、PAXGUSDT 永续 × MT5，以及同一 MT5 的两个不同品种。列表选择仅预览，保存后点击「设为当前组合」才启用；切换后需要重新连接、对账并手动启动。一次仅管理一个当前组合，有未平组、待确认订单或开仓运行任务时禁止切换。账户连接共用，组合文件不复制 API 密钥；各组合保留独立的品种、策略、费用和 Magic，历史记录保留并可按组合筛选。

同一 MT5 双品种固定卖 A、买 B，每组两腿使用相同手数，分别校验最小手数与步长；相同手数不代表相同合约数量或名义金额，收益分别按各自实际合约大小计算。当前支持 Windows 原生 MT5、USD 对冲账户，以及经终端盈亏计算接口核验的 USD 线性合约；纸面模式也需要该终端真实行情。请填写终端完整品种名称，并确认两品种为同一标的、相同报价单位。本版不自动换算不同报价单位、不自动续期合约，也不接管未登记的双品种外部仓位。到期／停盘或不支持的合约将阻止执行。

同终端两腿的成交佣金和 Swap 分别后台核对，平仓佣金仍用各腿每手单边预估值；两个返佣比例分别设置。MT5 报价读取、账户读取、历史查询和交易使用独立会话，账户与历史查询不插入双腿交易之间。同一个交易会话仍按顺序调用原生 MT5，不能保证两腿同时成交。程序外平仓按原开仓订单与不可变持仓标识回补；仅在平台成交原因确认强平后，才对剩余腿安排保护性平仓。重启后保持暂停，完成对账才能恢复新开仓。

交易台将当前组合、执行按钮和价差图提前，数量、策略、费用和保证金风险默认折叠；配置在各组合间独立保存，切换不会改写原组的开仓绑定与已锁定规则。

- **记录与持仓**：交易组、双边订单流水、币安持仓、MT5 持仓和币安挂单各自分页，每页 10 条；自动刷新保留页码，收益摘要仍统计全部记录。收益表的状态解释、费用核验口径、执行警告和敞口原因可悬停或键盘聚焦查看，未确认的持仓仍直接标为待核对。
- **交易台**：每组数量、策略参数、连接/对账/启动操作和实时价差。修改手数立即更新数量预览；「引擎当前每组」单独显示连接时实际采用的数量。
- **连接设置**：MT5、币安 API、代理出口 IP 与连接检查。说明及旧版手动纸面工具默认折叠。
- **记录与持仓**：交易组收益、订单回报、平台持仓对账和旧仓接管。

自动保存只代表写入本机配置。除单独点击「应用开仓阈值」外，手数、止盈、费用等参数需要先暂停新开仓，再「保存并重新连接」、持仓对账并手动启动；已开交易组继续按原规则管理。未连接、待对账或参数待生效时，启动按钮会禁用并显示下一步。连接检查期间仍可暂停新开仓；已有策略操作继续统一处理；正常程序组双边平仓并发发出。

新开仓保证金不足或保证金计算暂不可用时，仍允许建立连接、读取行情、持仓对账及已有仓位接管／管理。连接界面单独显示开仓受限原因；账户身份、权限、品种等原有连接校验仍须通过。点击「启动自动开仓」时重新读取保证金，未通过则保持新开仓暂停；不影响已对账仓位的正常退出和用户请求平仓。保证金按“总手数上限减本机未平组已占手数”的剩余额度计算，包含已接管组，避免重复要求已有仓位的保证金；未登记的平台仓位不会增加策略额度。原程序仓位重启后应先对账恢复，只有未登记的外部仓位才走接管流程。实际发送 MT5 订单前仍执行终端预检查；本改动不向双腿执行之间添加保证金查询。

## 暂停与已有组退出规则

交易台的「启动自动开仓」和「暂停新开仓」为两个常显按钮，并单独显示新开仓状态。暂停阻止后续新建交易组及网格补仓，已有仓位继续按规则管理，已发送订单继续确认和处理；连接检查或其他页面操作期间仍可请求暂停。后台正在处理订单时，暂停等待当前执行操作结束，不撤销已发送的订单；页面显示等待服务端确认，不能把点击按钮当作暂停已经完成。

如需中途调整已有仓位，在「记录与持仓」的组操作中点击「调整退出条件与返佣」，或展开同名面板。先载入，再预览原规则与新规则，最后确认应用；可改止盈方式、收窄量／绝对退出价差、最低净收益、单组亏损限制、最长持仓时间及本组双平台手续费返佣比例。逐组退出单独修改，整篮子须统一修改全部当前成员。规则或成员变化后旧预览失效；成交待确认、恢复对账中、平仓中或异常撤回组不能修改。后续新仓继续使用主页面配置；新增篮子成员也使用主配置，并与现有成员的规则共同判断。主页面修改、后续新仓参数、总亏损限制和滑点保护不被此操作覆盖。

确认修改后从下一次有效行情检查起生效，条件已满足时可能立即平仓；最长持仓时间从原开仓时刻计算，不重新计时。规则与修改前后数值原子持久化并加入执行诊断。接管旧仓继续使用专用管理区。

## 手续费与收益口径

币安线性合约先按开平价差计算 USDT 盈亏，再将盈亏换算成 USD；MT5 盈亏按 USD 汇总。不会将开、平仓的两笔名义本金分别换汇。已平仓的收益换算汇率固定，后续费用核验只修正费用；旧版已平仓且成交完整的本机记录会在启动时按新口径重算。

逐组止盈同时检查本组价差条件和配置的最低净收益，下第一腿前会用缓存行情复查。若条件失效且尚未成交，继续持仓等待；若已有一腿平掉，则继续减仓处理剩余敞口。触发收益是下单前估算，实际滑点、费率及预计返佣到账差异仍可能使最终收益低于阈值。在“剩余敞口／原因”悬浮说明中可查看触发时预估，执行诊断保留触发阈值、收益和实际滑点。

币安完整 FILLED 回执缺少均价时，平仓流程立即有界补查一次原订单，不重新下单。失败仍保护暂停；已暂停的自动开仓不会自行恢复。平仓第二腿读取缓存更新报价，不增加终端行情或 REST 行情请求。开仓第二腿优先使用两边本机接收时间均在 250 毫秒内的有效缓存，同时遵守用户配置的更严格行情时效、时差限制；不足则走原同步报价查询。诊断中的 quote_source 区分 cache 与 refresh。开仓原敞口时限与重试次数不变。

费用不是全部实时实结：币安可自动读取账户费率，持仓中的已付费用缺少成交记录时暂估，未发生的平仓费始终预估；MT5 未回填的佣金使用每手单边配置。普通实盘组平仓后异步读取完整成交与费用记录，复核通过才显示已核验，延迟或失败时保留估算并重试。资金费来自平台记录并按组数量分摊；接管前历史成本由用户录入，纸面模式为模拟。为保持双腿执行速度，不在下单和平仓回报之间查询费用历史。

可以分别填写币安和 MT5 的手续费返佣百分比（0～100，默认 0）。填 30 表示返还正手续费的 30%，不是成交金额的 30%；两边分别计算已发生成交费用与预计平仓费用的返佣。用于策略判断的净收益 = 交易毛收益 − 已发生手续费 − 预计平仓费 + 资金费／Swap + 预计返佣。该净收益用于逐组／整篮子最低净收益及单组／总亏损判断，价差、时限和执行保护条件仍按原规则判断。实际成交手续费更新时重新计算返佣，不累计重复添加。

返佣按用户比例预计，不代表已到账；页面保留未含返佣的净收益和原始手续费，平仓后的含返佣结果也继续标明预计，不因手续费已核验而改称实际返佣。负手续费、资金费、Swap 及接管前历史费用不再计算返佣；佣金为 0 的费用没有百分比返佣。若平台返回的手续费已扣除同一笔返佣，对应比例应设 0，避免重复计算。本版不读取或确认返佣到账。MT5 按每手固定金额的返点不适用这一百分比设置。

主页面的返佣比例保存并重新连接后供新仓使用；已有组保留开仓时比例，需在记录页选组、载入、修改、预览并确认，下一次有效行情检查起生效，可能立即满足平仓条件。返佣计算只增加本机数值运算，不增加交易平台请求。

## 在平台手动平仓后的记录回补

实盘原生 MT5 连接后，后台使用独立的币安只读客户端及 MT5 只读工作进程，每轮完成后等待约 5 秒核对程序持仓数量；网络请求和历史查询不使用下单会话或交易执行锁。网络、终端和本机资源仍会影响核对时效，不能保证即时发现。检测到数量变化先暂停新开仓及自动处理，再按真实成交历史回补。回补记录不会重新开仓，也不会自动处理剩余敞口。

- 双边已平且成交能够唯一归属：记录真实成交价、数量、手续费、平台时间及 MT5 已结 Swap，交易组转为已平仓；开新仓保持暂停。其他尚未取得的费用继续标为待复核。
- 重启后停在「异常撤回／平仓中／成交待确认」的普通组也会检查：先只读查询原订单，再核对平台平仓历史。MT5 持仓已经关闭、当前票据查不到时，仍可通过原开仓订单和不可变持仓标识核验；不把历史订单号冒充当前持仓票据。原程序平仓已确认的组直接按现有成交结束，不重复追加外部成交。
- 只平一边或部分数量：仅回补已证实的成交，显示剩余仓位并转为需人工处理。点击「持仓对账」通过后，可请求平掉剩余仓位；也可在平台继续平仓，等待后续回补。
- MT5 按原开仓成交和不可变持仓标识归属，即使手动平仓的 magic／注释不同也能查找。币安须验证原随机客户端订单标识，且历史窗口内只存在一组可归属仓位；多组并存或交叠时不随意分摊合并持仓的平仓成交和收益。
- 历史未完整返回、存在挂单、其他方向／加仓、账户不符或核对期间仓位变化时，保留待核对状态；不会用仓位消失推算成交价格。历史自动读取限制在 180 天内，并限制总请求与记录数量。可处理连接恢复后的程序仓位；接管旧仓继续使用专用管理流程。

页面的后台核对提示与完整对账时间分开显示。后台主要发现持仓数量变化，并非对所有手动交易持续审计；数量相同的平后重开等操作仍需人工完整对账。外部成交以「平台外部平仓 · 已回补」展示，并进入执行诊断；其平台时间与本机回补时间不被当作程序下单耗时。

更新后连接双边行情，点击「持仓对账」。若提示平台空仓但本机旧组未结束，会立即请求后台重新核对成交；等待旧组变为「已平仓」且对账通过，再手动点击「启动自动开仓」。历史缺失或无法唯一归属时仍会阻止启动，可从记录页导出执行诊断继续排查，勿删除本机交易记录来绕过检查。

程序自开组发生平台强平时，后台先核对真实平仓成交、原订单归属及前后稳定的双边持仓。MT5 必须有成交原因 `DEAL_REASON_SO`（6）；币安必须由已签名的 `forceOrders` 强平历史（LIQUIDATION）精确匹配订单、方向、数量与均价。符合条件后，受影响组自动进入保护性平仓，先减少不配平部分，再结束该组剩余仓位；不再等待止盈或最低净收益。使用该组原有保护性滑点预算和重试上限，不新增对冲仓位，新开仓保持暂停。其他组仍按原规则管理。

手动平仓、止损/止盈、原因不明、历史缺失、归属不清、未完成委托或持仓仍变化时，继续暂停等待核对。接管组不进入此自动联动流程。只读后台约每 5 秒检查，历史与网络查询另需时间；保护性平仓仍需要有效行情与平台交易通道，不保证瞬间成交。未知回报只查询原订单，达到重试上限后等待人工处理。重新连接旧账户时，会尝试补查旧外部平仓记录缺失的原因；若证实强平且仍有对应仓位，也可能自动进入保护性平仓。

执行诊断的订单 `result.close_cause` 保留平台确认的原因；MT5 含原数字原因码和固定说明，不保存任意成交注释。`liquidation_protection_armed` 记录安排保护性平仓的事件，组内 `liquidation_recovery` 保留本机发现/安排时间和当时剩余数量。这里的发现时间是本机核对时间，不是平台实际强平时间；仍需根据订单流水确认另一腿是否真正平完。

未连接、待对账、异常处理或成交未确认的组显示「收益待核对」；剩余量标为日志数量，避免被误认为平台真实持仓。服务端保留上一份估值，前端不按新行情继续投影；完成核对后的普通持仓恢复估值，已平仓记录仅继续复核实际费用。每组「本组已锁定规则」的展开／收起状态及键盘焦点在行情和状态刷新后保留。

## 双边强平风险提醒

交易台顶部在实盘连接后显示两张风险卡片，只读展示与分级提醒，不会自动暂停、减仓或平仓；纸面模式不读取真实账户风险。未连接、读取失败、字段缺失及数据超过 20 秒时明确显示未知或过期，页面断开后也会自行撤销旧的正常状态。

- **币安**：独立线程约每 5 秒读取合约账户及当前品种的持仓风险，不占用交易线程或 MT5 会话。距离按标记价计算：空头 `(强平价 − 标记价) ÷ 标记价`，多头 `(标记价 − 强平价) ÷ 标记价`；双向持仓展示最近的一侧及各方向原始数据。强平价为 0 时不能判为正常。账户保证金余额、维持保证金及可用余额包含其他品种；显示的是平台当时返回的预估强平价，会随全仓资金和持仓变化。
- **MT5**：复用原生终端已有账户快照，显示账户净值、可用保证金、保证金水平，以及经纪商的追保和强平线。百分比模式按整个账户净值／占用保证金计算，同时检查经纪商阈值；金额模式仅展示经纪商原始阈值并标记未判定，不估算固定的黄金强平价。
- 展开「预警阈值与指标说明」可修改提醒线，自动保存后用于页面提醒，无需重新连接。初始值为币安距离预警 5%、危险 2%，MT5 保证金水平预警 200%、危险 100%；每侧危险线必须低于预警线。这些只是可调整的提醒参数，不代表安全标准或成交保护；快速波动、网络延迟与经纪商规则可能使强平先于提示发生。

## 快速开始（纸面交易）

### 1. 启动服务
```bash
# macOS 开发环境
python3 launcher.py

# Windows 构建包
双击 GoldPairLocal.exe
```

### 2. 配置纸面交易
1. 在「连接设置 → 币安连接配置」选择执行模式为「纸面模拟」
2. Mac 选择「MT5 MCP 真实行情（Mac只读）」；Windows 选择原生 MT5 终端
3. 输入本次会话的 MCP Token（或设置 `MT5_TERMINAL_MCP_TOKEN`），点击「检查 MT5 连接」
4. 在「交易台 → 策略与自动执行」点击「连接双边行情」
5. 点击「启动自动开仓」开始纸面交易
6. 观察下方实时价差图表和持仓组状态

「连接设置 → 旧版手动纸面工具」中的旧版纸面引擎只用于手动单步撮合验证，不会在后台持续运行；应用每次重启都会将它恢复为停止状态，但保留已有模拟持仓供查看。

### 3. 图表显示
- 连接成功后，下方的「实时价差」会自动显示本机积累的可成交价差
- 图表显示入场/退出 Bid/Ask 口径折线、开仓阈值、每组止盈线和策略开平仓标记
- 可切换 1 小时至 30 天，拖动或缩放后可用「回到最新」恢复整个窗口
- 图表上方显示当前价差、窗口均值和范围，下方明确标出历史覆盖时间和采样数
- 行情重连或从记录页返回交易台后，会补读本机历史；更换同一账户的终端程序路径保留原市场历史，不混入其他账户／经纪商／品种。灰色区分采样缺失与无效报价，折线保持断开；停机或断线期间未采集的真实 Bid/Ask 无法补造。
- 收益随有效报价估值；完整平台持仓对账并非持续进行，页面显示上次完整对账时间和报价过期状态。在平台手动改仓后须重新核对，不能把报价更新视为仓位核实。每组可展开查看保存的止盈、亏损、持仓时限和滑点规则；主页面修改普通参数不会覆盖已有组，开仓阈值需点“应用”，风险提醒阈值保存即生效。

## 完整配置流程

1. 在 MT5 登录自己的交易账户并保持终端运行；账号、服务器和交易密码由 MT5 管理。
2. 双击 GoldPairLocal.exe，程序启动本机服务并打开浏览器。保留控制台窗口；关闭会停止本机服务。
3. 点「检查 MT5 连接」。单个终端可自动查找；多个终端时展开设置指定 terminal64.exe。
4. 单个 XAU/USD 品种可自动识别；多个黄金品种时从候选列表选定，再检查。部分经纪商把黄金 CFD 的基础货币返回为 USD，程序会在连接检查中额外验证合约盈亏换算，通过后才能应用规格。
5. 核对实际账号、服务器与黄金品种。检查成功后会自动应用最小手数、步长和每手盎司，并自动计算等盎司配平数量；修改每组手数后会重新计算。
6. 页面参数在停止输入约 0.8 秒后自动保存，也可点击“保存连接与策略配置”。只有服务端确认写入后才显示“已保存到本机”；未保存的普通输入按字段保留浏览器草稿，刷新会先恢复本机配置再合并草稿。切换执行模式或适配器保留目标账号、服务器和品种；已保存规格可回显，但不代表重新通过了连接检查。API Key、Secret 和 MCP Token 会保存到本机 `data/config.json`（Windows 包为 `%LOCALAPPDATA%\\GoldPairLocal\\config.json`），刷新或重启后会恢复；页面提供“清除已保存凭据”。不要把该文件或 data 目录共享给他人。可先在「连接设置 → 币安连接配置」点「检查币安连接」，纸面模式检查公开行情与规格，实盘模式还检查账户交权限、持仓模式和手续费率；检查不下单。然后在「交易台 → 策略与自动执行」连接双边行情，应用会读取两个平台的实际合约规则并检查等黄金数量是否可下单。
7. 先在纸面模式观察实时入场/退出价差折线和持仓组；实盘前，在 Windows 终端完成连接和对账，最后由使用者点「启动自动开仓」。

账号与服务器均可留空进行首次检查；应用结果后会保存为目标身份。后续检查发现终端登录到其他账户时会拒绝应用，不会自动切换账户。
数量预览可使用已保存的 MT5 规格即时计算，但会明确标记为预览；修改连接身份、程序重启或连接检查超过五分钟后，执行级数量校验仍需重新检查 MT5。

只读检查可在自动交易关闭时运行。实盘执行需要：
- MT5 工具栏启用 Algo Trading / 自动交易；
- 工具 → 选项 → EA交易中取消「禁止通过外部 Python API 自动交易」；
- 使用交易密码登录；投资者密码只有只读权限。
检查页会提示这些问题，但不会自动更改终端权限，也不会发送测试订单。

## 执行模式与策略

方向固定为：**卖币安黄金永续，买 MT5 黄金**。每一组按 MT5 合约大小计算盎司数，再按币安的最小数量、步长、最大市价单数量和最低名义金额检查；不能等量配平时，应用拒绝启动。

- `paper`：纸上交易模式。使用币安正式环境行情和真实 MT5 行情；Mac 通过本机 MCP 读取账户及规格，并可配合 EA 推送行情；任何一边都不发订单。适用于策略验证和参数调试。
- `live`：实盘交易模式。必须选择 Windows MT5 原生终端，连接真实币安账户和当前已登录的 MT5，允许真实下单；如果仍选择 MCP，页面会保留选择并提示不兼容，连接实盘时拒绝启动。MT5 密码不在本应用中填写；币安 API Key/Secret 从本机配置读取，也可以在页面更新。完成账户与持仓对账，并点击「启动自动开仓」后才可能发送订单。

币安可使用单资产模式，也可使用多资产模式。多资产模式下程序会读取资产明细，只有 USDT 存在余额或未实现盈亏时才允许实盘连接；若检测到 USDC、BNB 等非 USDT 资产非零则拒绝启动并列出资产名称。页面显示的是 USDT 自身的钱包与可用余额，不把多资产账户总净值误标为 USDT。程序不会切换资产模式、执行万向划转或调用提现接口。

币安持仓模式支持单向和双向。程序在实盘连接时自动读取持仓模式；双向模式下，永续侧开仓和回补都明确使用 `positionSide=SHORT`，并按 LONG/SHORT 分开对账。策略只管理自己的空头腿，发现账户存在多余多仓或数量不一致时会拒绝启动。

入场价差 = 币安 Bid × USDT/USD − MT5 Ask；退出价差 = 币安 Ask × USDT/USD − MT5 Bid。可选择每组或整篮子退出、按收窄幅度或目标价差止盈；选择后只显示对应的幅度/目标输入框。每一组在开仓时锁定参数；后续修改仅影响新组。Magic 只是 MT5 订单隔离标识，已收入高级设置，一般不需要修改。

可配置项包括每组手数、自动开仓阈值、最大组数、总手数上限、重复开仓间隔、滑点、报价时效、最大单边敞口时间、最低净收益、单组/总亏损退出及最长持仓时间。可选启用网格补仓：每次当入场价差达到“开仓阈值 + 网格间距 × 补仓次数”时新增一组等量双边仓，最多补仓次数和总手数/持仓组数上限共同生效；建议网格使用“整篮子平仓”。正常止盈可要求最低预计净收益；止损、持仓超时和异常减仓不会被最低净收益阻止。

页面会根据模式和策略开关只显示当前有效的输入：“价差收窄”与“目标退出价差”不同时显示；实盘模式不显示纸面资金费、纸面 MT5 持仓费和旧版纸面撮合控件。

页面显示最新双边 Bid/Ask、报价时间、入场与退出价差折线、窗口统计、门槛/止盈线、开平仓标记、策略组、剩余敞口、预计净收益和事件日志。最近 24 小时保留高频采样，更早数据按分钟归档并保留 30 天；图表按观察窗口自动降采样，支持 1 小时至 30 天。刷新页面或切换纸面/实盘配置后，同一交易所品种仍会合并已有历史；如果过去没有运行采样，系统无法补造历史数据。这里故意不混入按 K 线收盘价反推的参考曲线，以免将“历史中间/收盘口径”误当成当时真正可成交的价差。

「06 · 收益与订单」按交易组显示开平仓时间、币安/MT5 配平量与开仓成交金额、交易毛收益、手续费、币安资金费收入/支出、MT5 swap、持仓期间实时净收益和已平仓净收益。双边订单流水另行列出每笔平台订单的申请数量、成交数量、成交价、成交金额、手续费、状态和平台票据。实盘平仓后，程序会用币安成交/收益历史和 MT5 deal 历史复核；复核前明确标为估算。

币安最优 Bid/Ask 优先使用官方 WebSocket `bookTicker` 长连接，断线自动重连并回退 REST。若客户网络无法直连币安，可在页面填写无账号密码的 HTTP/Mixed 代理（例如 `http://127.0.0.1:7890`），REST、WebSocket、账户检查和实盘下单会统一走该代理；留空则直连。“获取币安出口 IP”会沿相同应用代理检测当前公网地址，便于复制到币安 API 白名单。该地址只代表检测当时结果；正式交易应使用固定出口，代理节点、家庭公网 IP 或代理分流规则变化后必须重新检测并更新白名单，最终以币安连接检查结果为准。MetaTrader5 Python API 没有 tick 回调/WebSocket 接口，因此实时推送由只读 EA 提供；未接入 EA 时保持 MT5 工作进程和终端会话，默认每 250 毫秒轮询最新 tick。报价最大年龄默认 3000 毫秒。

## 净收益与费用数据

- USDT/USD：默认自动读取币安 `USDTUSD` 资产指数，30 秒更新；数据暂时不可用时保留上次值并告警。
- 币安佣金：实盘连接时从账户费率接口读取 taker 费率；持仓期间按费率估算，平仓后以 `userTrades` 实际 commission 复核，非 USDT 费用资产会换算为 USDT。下单及未知订单查询路径不等待手续费历史，避免延误第二腿对冲。
- 币安资金费：纸面模式使用人工预估，这不是下单手续费；实盘持仓期间每分钟读取已入账的 `FUNDING_FEE`，并在多组重叠时按数量分配。
- MT5 佣金：MT5 Python API 没有通用的“账户佣金费率”字段；实盘成交前使用页面预估，成交后立即读取 deal commission/fee 覆盖。
- MT5 持仓费（Swap）：纸面模式使用人工每手每日预估，这不是 MT5 开平仓佣金；实盘持仓直接读取当前 position swap，平仓后再用成交历史复核。MT5 开平仓佣金单独按页面的佣金预估填写，成交后以 deal commission/fee 覆盖。

因为各 MT5 经纪商的佣金表不是 MT5 Python 标准属性，这一项无法在首笔成交前保证全自动。本版实盘限定 MT5 账户币种为 USD，避免将其他账户币种的佣金误当成 USD。

连接检查仍以独立进程在 18 秒内完成；持续 MT5 会话也放在独立进程，终端卡住不会卡死网页。

## 成交、异常与对账

每次订单先写入本机 SQLite 日志，再向平台发送；使用唯一订单标识。网络超时、未知回报或 MT5 调用超时都不会直接重发，而是先查询订单、成交和持仓。默认开仓先以 IOC 卖币安，再买 MT5（也可配置为 MT5 优先），并受最大单边敞口时间和滑点预算限制。实盘发送 Binance IOC 前先使用现有 `bookTicker` 最优档数量做零额外请求检查；最优档足够时直接发 IOC，仅在最优档不足或数量缺失时读取浅层订单簿。订单簿读取失败或滑点范围内深度不足时不会发送该 Binance 订单。

- 币安第一腿在下单前因盘口不足或深度读取失败被拦截，且双边均未下单：跳过本次机会，保留自动开仓运行状态；经过已设置的开仓冷却时间后，按最新行情和阈值重新检查，不连续追单。
- 若 MT5 已先成交，再遇到币安盘口拦截，仍暂停新开仓并保护性平仓。实际订单部分成交、被交易所拒绝或状态不明也保留原有暂停逻辑；状态不明时先对账，不重发。
- 平仓某一腿成功：不反向重开，继续处理剩余腿；达到重试上限后进入需人工关注状态。

平仓请求按平台分别计数，`close_retry_limit` 是每个平台的实际请求上限（含首次）；等待报价和查询原订单不消耗请求次数。计数与订单意图一起持久化，未知回报只查原订单，不重复平仓。旧版已达到上限或需人工处理的组不会因升级自动获得新额度；使用“重试平仓”才开启新一轮额度。接管组完成一组等量减仓后沿用原有进度重置规则。

正常程序组两边数量配平、订单已确认时，双边平仓采用并发：使用同一份最新有效报价，在一个 SQLite 事务中持久化两张独立订单意图、各平台计数和两条事件，再同时调用 MT5 和币安适配器。两张意图要么一起提交、要么一起回滚，比逐张落盘少一次同步提交。线程只处理网络调用，回报、校验、数据库和状态变更仍由原执行线程依次处理，先返回的回报先落盘；双边调用返回前不查询或撤销这批订单。两边独立遵守普通滑点，可能不同步成交或仅一边成交。已确认残余敞口继续单独保护性减仓；回报未知只查原订单，不重发。开仓、接管票据和开仓异常撤回保留逐笔执行。

双边意图保存后再次校验报价；若已过期，本批均不发送，等待新报价且不消耗实际请求额度。线程调度未启动则进入需人工处理状态，本批不会发送；明确重试后才恢复减仓。重启只恢复持久化意图和回执，原订单未确认前不发送替代订单，新开仓仍须对账后手动启动。诊断中的 `dispatch_mode`、组内 `close_batch`、`dispatch_queue_ms` 和 `last_dispatch_gap_ms` 分别记录执行方式、批次、意图全部落盘至各调用的单调耗时和最近双边调用间隔；两次适配器调用间隔不等于成交时间差。

正常双边退出遵守普通滑点。任一腿已经确认减仓、形成不配平敞口后，剩余腿使用本组已配置的 `unwind_slippage_usd` 保护预算，价格随有效新报价更新；不再等待净收益转正，也不反向补仓。限价仍可能不成交，达到每个平台请求上限后须人工处理，程序不会无限重试或改发无价格限制的订单。诊断中的 `close_attempts`、`close_protection`、`close_halt` 和订单 `slippage_mode` 记录计数、保护模式及停止时的剩余数量；后续平台外部平仓不会抹掉停止证据，表格原因悬浮提示也保留这段经过。

MT5 平仓返回成功码 10009、完整请求手数但价格为 0，且原订单仍显示待处理时，提供最多 300 毫秒的本机核对期，沿用原订单查询退避。处于平仓中的组仍阻止新开仓执行；核对成功且双边平仓完成，可保持原运行状态。超时、未知部分成交或其他错误仍暂停；核对期不延长开仓敞口期限，已经暂停或重启的程序不会自动恢复开仓。
- 程序重启或账户断线：暂停新开仓，须手动连接原账户并完成持仓对账。连接成功只说明通道可用，不代表所有订单已确认。普通策略组逐张核验 MT5 票据、所属开仓注释及剩余数量；即使总手数相同，逐组不一致也拒绝通过。
- 普通组或接管组已请求平仓／保护性撤回时，未知回报先继续查询，不重复发单；恢复状态中也会定期核验两边实际仓位，核验通过后继续原平仓流程，新开仓保持暂停。升级保留旧日志，也会继续其中尚未完成的平仓请求；不会自动将异常组转为正常持仓。
- MT5 未确认回报保留订单编号，优先用订单编号查询成交历史，不能把成交编号传给订单查询参数。旧日志缺失编号时，从唯一开仓注释与持仓标识恢复历史，最后才查询开仓前后各 24 小时的历史；不改变系统、报价或成交时间。已出现的部分成交还要核验订单已终结和成交总量，空历史不等于未成交。
- 行情缺失、过期时，已连接通道仍可按退避规则读取未确认成交，但不发出平仓指令。正常 MT5 成交回报只读取实际持仓票据，不等待成交历史或手续费查询；异常回报才进一步核对订单和成交历史。
- 「记录与持仓」同步显示操作结果与错误。成交未知时显示待确认数量和待核对收益，不把 MT5 未确认回报当作零持仓；尚有开仓、平仓或异常组时禁用启动新开仓。
- 只处理带本程序 Magic 标识和唯一注释的 MT5 仓位，拒绝把其他手工仓位纳入策略。

普通实盘组持仓稳定后，由现有独立只读观察线程每轮最多核验一张开仓订单的实收手续费；币安核对原订单身份、完整且不重复的成交明细及手续费，MT5 使用严格的原订单成交历史。查询失败保留估算，30 秒后重试，不暂停交易、不重发订单；查询期间出现新订单、平仓或规则变更会丢弃旧结果。正常下单路径不增加历史查询；只读查询不持有执行锁，成功后短暂更新并持久化费用，净收益与退出判断使用更新后的费用。成交手续费已核验不代表资金费或未来平仓费已确定。收益摘要分开显示所有组累计成交手续费与当前持仓预计平仓费，返佣继续单列为预计。

平仓后会按币安订单成交记录、MT5 成交历史和资金费记录复核费用；复核前显示的是预计净收益。普通组逐订单核对历史成交数量，空列表或不完整记录不会覆盖原有费用，也不会标为已核实；60 秒后重新尝试。资金费归属依赖本程序是该合约唯一受管仓位，因此对账不一致时不会自动归属。

## 已有持仓接管

1. 连接实盘后，展开图表下方“已有持仓管理”。点击“读取已有持仓”；手工仓位导致对账不一致是正常的，已读取明细仍会显示。
2. 选择要接管的 MT5 多头票据，所选黄金数量须等于当前品种的全部币安空头。首次接管要求没有本程序未平交易组、双方当前品种没有挂单；目前不支持反向持仓、分割 MT5 单个票据或仅接管部分币安空头。
3. 核对原始开仓 USDT/USD、接管前双边手续费及资金费净收入。未知数据不能直接当作零；当前 MT5 Swap 自动读取，不要重复填入。平台均价是当前持仓成本，不代表原始逐笔成交或同一时刻的盘口价差。
4. 设置独立的收窄目标和篮子最低净收益，预览配平与成本。确认时重新核验平台持仓，预览 2 分钟有效。确认只保存接管记录并对账，不下单，不自动启动管理；重复确认同一预览不会重复导入。
5. 点击“启动已有仓位管理”后，旧仓才按“收窄达到目标且估算净收益达标”退出。可能立即触发真实平仓。旧仓默认暂停，与新开仓开关独立；退出条件要先暂停旧仓管理再修改。

接管使用一个独立旧仓篮子，本版旧仓不自动补仓、不与新策略篮子合并止盈；新策略原有网格仍独立运行。旧仓占用总手数额度，不受新仓的逐组止损、整篮子止盈或最长持仓参数影响。全平按钮会处理已接管仓位。

接管记录和启用时保存的退出参数保存在本机数据库。重启/重连会暂停旧仓管理，需重新对账后手动恢复。接管期间绑定原 MT5 账户/品种及币安 API Key；不要切换账户、修改同品种仓位或用其他程序同时管理。检测到数量或票据身份变化会暂停并要求重新核对。

执行按 MT5 票据逐个平仓，并只按实际已平数量平币安对冲腿；两平台无法保证原子成交。暂停旧仓管理不会撤销已发出或正在核实的平仓。手续费、资金费分摊和预估退出费用不保证最终实际净收益；原始历史成本仍标为用户确认的估算，接管后程序发送的成交费用会在平仓后再核验。

## 采样、延迟与成交价差

MT5 同一个 tick 的有效期从首次本机观察时计算，重复轮询、EA 回退到轮询、重新连接及第二腿前读取均不刷新其年龄；币安行情继续更新也不能让旧 MT5 tick 恢复有效。观察时间在其他平台的阻塞请求之前记录，跨平台原始时间差仍仅用于诊断。

高频行情以本地采样时间作为唯一标识；同一时间戳和已完成分钟归档点不会被后续数据覆盖。最右侧当前分钟会持续增加新采样，这是实时监控的正常表现。250 毫秒仅为兼容轮询的默认间隔，不是成交保证时间；接入推送后由新报价唤醒策略。

触发信号后，程序会记录信号时的入场/退出可成交价差。第一腿成交后会重新读取双边报价；报价过期、超过单边敞口时限、部分成交或状态未知时，程序才会暂停新开仓并按已成交数量处理未对冲敞口。两边都完整成交但实际入场价差低于触发阈值时，不会为了“修正报价”立即反向平仓；该组以实际成交价差作为后续管理基准，并在页面标记执行偏差，避免无意义的手续费往返。订单流水分别显示监控价差、实际成交价差和偏移；实际成交价差按两边成交均价与对应成交汇率计算。

原生 MT5 Python 接口没有 WebSocket 或推送回调，本版新增只读 EA 作为行情推送通道；交易仍由既有原生适配器执行，正常程序组双边平仓并发发出。未安装 EA 或 EA 报价过期时，界面显示轮询兼容，继续用 Python/MCP 获取行情。账户、持仓和 Swap 快照约每 2 秒刷新。行情按 tick 首次本机观察时间校验年龄和双边时差，不会以收到心跳或重复轮询的时间伪装新报价。

### 安装 EA 实时行情推送

1. 在页面检查并应用 MT5 账户和黄金品种，展开“加速行情：MT5 EA 实时推送”。点击“准备 EA 与本机参数”，下载 `.set` 参数文件和已编译的 `GoldPairQuotes.ex5`。
2. MT5 中选择“文件 → 打开数据文件夹”，将 EA 放进 `MQL5/Experts`，在导航器刷新，然后挂到对应黄金品种的图表。输入参数中“加载”刚下载的 `.set` 文件。
3. MT5 的“工具 → 选项 → EA 交易”允许访问 `http://127.0.0.1`。接收端仅监听本机 8767 端口，EA 使用 Socket 长连接，不需要额外 Python 桥接程序或 DLL。
4. 页面连接双边行情后，查看 MT5 状态是否为“EA Socket 推送”。EA 与页面配置的账号、服务器、品种必须一致。Mac 可结合 MCP 验证推送和纸面策略，Windows 实盘仍需原生适配器、对账及手动启动。

EA 只发送报价，不接收或发送交易指令。它在 `OnTick` 推送最新 Bid/Ask，定时器只负责重连和心跳；同一身份只允许一个推送连接，拒绝错误口令、非法报价、乱序时间、重复序号。口令保存在本机 `data/quote-push.json`（Windows 为应用数据目录），参数文件包含同一口令，不要共享；构建包和 Git 不包含本机口令。若 MT5 日志出现 `incorrect parameters (32767)`，表示 EA 输入里的 `LocalToken` 为空或端口无效：重新点击网页“准备 EA 与本机参数”，在 EA 的“输入”页点击“加载”选择新的 `GoldPairQuotes.set`，再启动 EA；只复制 `.ex5` 而不加载 `.set` 不会接通。

### 图表长连接与延迟

图表通过 SSE 长连接增量接收行情，断线自动重连，短时断线可补发，超出缓冲区则重新载入本机历史。报价缓存与交易工作线程分开，订单回报等待期间行情仍会接收、保存和推送。新报价会唤醒策略，无需等待固定 250 毫秒；正常程序组双边平仓并发发出，保留开仓逐笔执行和原有冷却/仓位限制。

图表绘制使用 `requestAnimationFrame` 合并浏览器同一帧内更新，不以 250 毫秒定时器限制图表；后台标签页或负载高时绘图可变慢，不影响后台策略。最近一分钟逐报价显示，较早曲线按固定 UTC 时间桶稀疏展示，已有时间戳的样本不会被重写。原始策略计算独立于图表缩放和稀疏展示。

页面显示行情通道、两边报价年龄和本机收到时间差；同时保留两边原始时间差供诊断。MT5 经纪商服务器时间可能是 UTC+3 等时区，因此原始时间差大不代表网络延迟，交易校验使用本机收到时间和报价年龄。订单流水展示“采样→调用”“意图落盘”“适配器调用”的本机耗时；适配器调用包含内部校验，不是交易所撮合的精确时间。EA 回调、磁盘持久化、网络、账户核验和适配器执行均会影响延迟：不会承诺逐 tick 无遗漏、固定毫秒成交或两边原子成交。必须在目标电脑、经纪商和网络上测量真实延迟。

## 执行诊断导出

账户快照、USDT/USD、持仓资金费及已平仓费用核对在独立后台运行，不在策略轮询中等待网络。账户快照和费用历史各用独立的 MT5 只读工作进程，避免同一会话排队影响交易。后台仅短暂取得交易锁捕获或发布结果，查询期间释放锁；连接、配置、相关订单或持仓组归属变化时丢弃旧结果。已平仓费用每次最多核对一组，数据不完整保留估算，至少 60 秒后再核对该组；不把未返回费用当成零。

账户快照每 2 秒调度，汇率每 30 秒、持仓资金费每 60 秒调度；网络耗时不包含在这些间隔内。账户快照失败、交易权限关闭或超过 15 秒未刷新时，暂停新开仓，已有仓位仍进入原有退出/减仓管理；快照恢复不会自动启动开仓。下单前的原生校验、归属核验、数量/滑点检查、原始敞口时限和订单意图落盘均保留。账户连接、恢复对账及接管归属检查仍保留必要的同步读取。

在“记录与持仓”展开“技术事件日志”后点击“导出执行诊断”，下载 JSON 后可发送分析。包含最近 200 组持久化记录：触发价差、每一腿下单前的双边报价、成交数量/均价、实际配对价差和偏移、单腿意图落盘与适配器调用耗时，以及开仓/平仓开始到整组确认完成的耗时。组与订单 ID 替换为导出内编号；不导出凭据、账户、服务器、平台票据、路径和原始错误文本，仍包含交易时间、价格和数量。技术事件仅保留最近 2000 条中与这些组/订单关联的白名单字段。

`latency` 为当前进程及当前连接的内存统计，重新连接或重启清空，`mode` 区分纸面/实盘。每阶段最多保留最近 512 个样本，导出时计算中位数、P95、最大值，并保留本连接累计样本数；统计不调用交易平台、不增加日志提交，不能恢复旧进程中未持久化的统计。

`exit_observations` 用于分析“图表碰到退出线却未平仓”：记录策略实际检查时的退出价差、目标、锁定规则版本、净收益与费用/预计返佣，以及双边报价年龄、时差和有效性。固定原因包括价差未达标、达标但净收益不足、整篮子其他成员未满足、等待有效报价、等待对账、未启用接管管理，以及第一腿前复查失效；触发退出也留证据。整篮子记录加权入场、篮子净收益和受阻成员数，图表的单组目标线不等于整篮子目标。

该记录仅保留内存中最近 512 段，原因、规则、报价有效性分类变化或每 30 秒开启新段；`first`/`latest` 为该段首末证据，`samples` 为检查次数，`min_exit_spread`/`max_net` 为段内极值，两者未必出现在同一时刻。无效报价或恢复等待提前返回时不重新估值，缺失收益不能当作零。重新连接或重启清空，出现问题请先导出再重启。采集不增加平台请求或数据库提交；仅导出时读取内存并匿名化组 ID。图表与策略独立取样，未被策略取用的瞬时行情、旧版未采集的瞬间及超出容量的记录不能追补；内存证据和数据库快照也不保证同一时刻。

| 阶段 | 含义 |
| --- | --- |
| `quote_wait_ms` | 最新一侧报价首次被策略取用时，距本机接收的时间；重复缓存不重复统计 |
| `binance_quote_age_ms` / `mt5_quote_age_ms` | 策略取用时两侧各自的本机报价年龄 |
| `decision_ms` | 一次有效策略轮询中的估值与开平条件评估，扣除订单执行及日志提交阶段 |
| `strategy_pass_ms` | 一次 `engine.tick` 总耗时，含其中的执行和确认，不能当成纯计算耗时 |
| `intent_journal_ms` | 原有订单意图同步落盘耗时 |
| `binance/mt5_open/close_request_ms` | 各腿适配器调用耗时，含内部校验及可能的补查 |
| `confirmation_query_ms` | 后续原订单确认查询耗时 |
| `pair_open_ms` / `pair_close_ms` | 双腿从开始到整组确认耗时；无法重建的重启记录不统计 |
| `maintenance_*_ms` | 后台账户、汇率、资金费和已平仓费用任务耗时 |

诊断格式 v2 还包含最后持久化的启停/恢复状态、暂停时间及固定原因分类、启动/暂停/重启事件、下单初始回报与后续查询的超时预算、耗时、平台状态和数字错误码。初始网络超时不会被后来的成功查询覆盖；任意上游错误原文不导出。旧版本没有记录的字段无法追补。运行状态是数据库快照，不代表导出时重新核验了平台持仓；事件历史受最近 2000 条上限约束。

`receipt_schema_version: 1` 表示支持平台回执字段诊断。`receipt` 保存原回执白名单中的字段类型和可解析数值，区分缺字段、null、零值、非法格式；币安保留 `avgPrice`、`cumQuote`、`executedQty`、数量、限价、方向、平台时间和归一化均价的来源。MT5 保留 `order_send` 的返回码、外部返回码、volume、price、bid/ask；同次调用通过历史补到成交，也不覆盖直接回执。`precheck_receipt` 单列 `order_check` 返回码；原生返回 None 时尽可能保存 `last_error` 数字码。HTTP 错误保留 HTTP 状态码与平台数字错误码。本机字段校验失败单列 `validation_issues` 固定分类。

撤单记录保存第一次及最近一次调用的返回、时间和耗时；`returned` 只表示调用正常返回，不证明已撤销，后续仍查询原订单。平台订单／成交／请求编号只记录有无，原始注释、请求回显和错误原文不保存到回执快照。新增字段复用已有回报和状态提交，不额外访问平台，不增加正常路径的同步提交；重复查询仍按原规则限频保存，首次和最近一次查询保留在订单中。历史版本未采集的原回执无法重新还原。

MT5 未确认成交还会记录首次未通过及最近一次查询的核对步骤：是否持有订单／成交／持仓编号（只导出有无）、历史读取是否为空或失败、归属匹配数量、订单终态与成交总量核验结果。按订单编号查询无匹配成交时，依次尝试对应持仓和有界时间范围；仍严格核验品种、策略标识、方向及原订单归属，不按相近时间、价格或数量认领。后续原生查询统一使用终端实际返回的品种名称。页面显示当前卡住的核对步骤。相同的未确认结果最多每 30 秒记录一次，首次查询、快速确认结束和成交／归属变化立即记录；查询频率不变，正常下单路径不增加历史查询或日志提交。

已平仓费用复核在独立只读后台执行。MT5 经纪商改写成交注释时，按原订单编号调用严格原生成交核验；只有编号、完整成交数量和均价一致，且佣金与 Swap 字段完整时才采用。手续费、Swap 和资金费整套核验完成后一次发布，失败保留原估算；`cost_verification_stage` 使用固定分类记录卡在币安费用、MT5 费用还是资金费阶段，不导出上游错误原文。

新增记录仅使用本机时钟，复用现有状态提交，不增加正常下单路径的交易接口调用和同步提交次数。导出仅在点击时通过独立只读 SQLite 连接读取，不获取交易线程或日志写入锁。额外字段仍会增加少量序列化和存储开销，导出也会消耗本机资源，不能保证绝对零影响。下单前同步保存意图用于断线恢复，继续保留。

币安第一腿明确返回 FILLED、数量完整但成交均价为 0 时，在原始敞口期限内先做一次有预算的确认查询，核验成功才继续第二腿；查询未确认仍暂停，超时确认仍走保护性撤回，不延长期限、不自动恢复已经暂停的新开仓。正常完整回报不增加查询。

MT5 第二腿返回成功码 10009、完整请求手数但成交价为 0，且原订单对应的持仓和单笔成交已严格匹配、订单仍短暂显示待处理时，保留原开仓确认期限，按原有退避查询原订单。只有订单终态和完整成交数量、价格均核验通过，才完成双边开仓；不会只凭成功码或持仓数量认定成交。超过原期限、部分成交或手动暂停后仍走保护处理。正常完整回报不增加查询或同步日志提交；无有效行情时也会记录期限结束并暂停，待成交确认和行情恢复后减仓。原生接口调用可能超过剩余时间，迟到的核验不恢复开仓。

未知订单只查询、不重发。开仓确认查询等待最多 1000 ms，并受原始单边敞口窗口剩余时间约束；该 HTTP 参数并非总耗时保证，实际超时后仍须确认原订单再减仓。近期未确认订单在快速重试结束后按 500 ms 间隔继续查询，10 秒后降至 2 秒。原始敞口期限不会因重试刷新；迟到的第一腿确认只进入保护性平仓，处理完成后仍须手动恢复开新仓。

本机收到回报不等于交易所撮合时间；查询确认另列，不能据此认定实际成交耗时。整组耗时包括双边执行、日志提交和可能的查询等待，截止组完成确认前，不含最后一次组状态提交；重启后不重建单调计时。缺失字段表示旧版未记录或无法确定，不补零；纸面模式速度不能代表实盘。手动/保护性平仓以首次执行报价作为价差基准。

## MT5 黄金品种识别诊断

Windows 原生 MT5 检查已连接账户但无法确认黄金规格时，页面显示已读取的品种名称、描述、基础货币 `currency_base`、盈利货币 `currency_profit`、预付款货币 `currency_margin`、自定义标记 `custom`、合约量、计算/交易模式及手数规则，并列出未通过的字段。空值与未返回分别标明；预付款货币不作为基础货币判断，未验证的合约量不标成盎司。把这段文字复制或截图即可进一步核对经纪商字段。

原始字段诊断复用本次检查已获取的 `symbol_info`，不额外查询品种，不加入下单或平仓链路。不会仅凭名称 `XAUUSD` 或合约量 `100` 自动放行。

黄金品种留空而自动识别失败，或填写的名称无法读取时，也会显示扫描数量及最多 5 个名称/描述相关品种的原始诊断。数据直接来自已有的 `symbols_get` 结果，不额外逐个查询终端。名称匹配只用于诊断提示与输入候选，标明“待校验”，不加入已验证合约列表，也不自动应用。检查须填写终端的完整品种名，例如 `XAUUSD`；仅输入 `x` 不会自动选择某个合约。

完整品种名仅大小写不同且对应关系唯一时，按已有品种列表匹配终端实际名称（包括保留经纪商后缀大小写），检查成功后保存并回填实际名称。例如 `xauusd` 可匹配为 `XAUUSD`；若存在多个仅大小写不同的品种，要求用户准确选择，不进行模糊补全，也不额外请求终端。

黄金 CFD 兼容：针对原生 MT5 返回基础货币 `USD`、盈利货币 `USD` 的非自定义合约，要求名称为 `XAUUSD`（可带后缀）、描述包含黄金及美元、计算模式为 CFD 或 CFD Leverage，并且账户币种为 USD。程序使用参考报价及符合手数规则的最小校验量，调用 `order_calc_profit` 核对做多／做空、价格上涨／下跌 1 美元的四项预估毛盈亏，与「手数 × 实际合约量 × 价格变化」交叉验证；四项通过后才按盎司应用规格。规格核验不要求参考报价在 5 秒内更新；没有有效 Bid/Ask 时使用明确标记的假设价格，仅用于盈亏计算，绝不生成交易行情或替代真实报价。原始基础货币仍保留为 USD，页面明确显示兼容校验通过。只有一个待核验候选时可自动选择后执行核验，多个候选必须指定完整名称。

四次盈亏预估仅在点击检查连接时执行，不发送订单，不调用订单预检查，不加入行情、开仓或平仓执行路径。标准 `XAU/USD` 字段的黄金合约沿用原有检查流程。非美元账户、其他基础货币（包括空值）、不支持的计算模式、接口失败或盈亏不一致均不通过兼容校验，并显示具体原因；这不是通用的任意经纪商／任意黄金产品适配。

规格核验与行情可用性分开显示：缺失或无效 Bid/Ask 不作为有效行情返回；报价原始时间与本机相差过大时，显示具体 Bid/Ask、原始时间戳和毫秒差，提示可能报价未更新或时钟偏差，不笼统归为品种识别失败。无效行情、观察后一直未更新的过期行情仍由原有实时检查阻止交易；兼容核验的假设价格不写入行情、执行快照或配置。

MT5 时间基准提示：原始 tick 时间与本机相减不等于已测得的行情或网络延迟，单次连接检查也无法确认报价持续更新。页面不再把负差值显示为「负数报价年龄」，而是说明 MT5 原始时间比本机快／慢多少；接近整小时时只标为未确认的时间基准差异线索，不自动加减整小时、不更改 Windows 时间或时区。此类原始时间差放在时间提示中，真实缺失／无效报价和权限问题仍列为待处理事项。

运行时继续使用本机首次观察到同一 tick 的时间判断新鲜度，重复轮询或切换传输通道不会延长该 tick 的有效期；只有新的 tick 才刷新，报价时间倒退仍拒绝。币安签名使用独立服务器校时及单调时钟锚点，不使用 MT5 原始时间。若出现接近整小时的偏差，应先正常核对 Windows 自动对时，并在交易台观察实际 tick 是否持续更新，不能仅凭一张连接检查截图判定延迟或认定为经纪商问题。
